  3. GET SINGLE MATERIAL REQUEST (detail)
================================================================================

Endpoint:
  GET /api/v1/material-requests/{id}/

Frontend function:
  fetchMaterialRequest(id)
  File: material-request.api.ts

Example:
  GET /api/v1/material-requests/1/

Expected response:
  Same shape as CREATE response data (MaterialRequestDetail), including after dispatches:
  - items[].dispatched_quantity updated per line
  - status may be partially_dispatched | dispatched
  - timeline[] populated with dispatch events
  - extra_dispatch_items[] for items not on original request

Timeline entry shape:
{
  "id": "tl-1780633738054-abc1234",    // string or number
  "title": "Materials dispatched",
  "description": "Dispatched 15 units including 1 extra item(s).",
  "occurred_at": "2026-06-03T14:22:00.000Z",
  "tag": "dispatch"
}

Extra dispatch item shape:
{
  "id": "extra-1780633738054-19-x7k2m",
  "item": 19,
  "item_name": "Portland Cement (Type I)",
  "quantity": 5,
  "dispatched_at": "2026-06-03T14:22:00.000Z"
}

Dispatched display rule (frontend UI):
  If dispatched_quantity > requested quantity:
    Show as "10 +5" meaning 10 requested + 5 surplus (total 15 dispatched)

================================================================================
  5. DISPATCH MATERIALS (NEW — required for dispatch screen)
================================================================================

Endpoint (NOT in original draft — backend must add):
  POST /api/v1/material-requests/{id}/dispatch/

Frontend function:
  dispatchMaterialRequest(id, detail, payload, itemLabels)
  File: material-request.api.ts
  Screen: material-request-dispatch-screen.tsx

Currently when mock OFF:
  throws Error("Material request dispatch API is not available yet.")

Request payload (MaterialRequestDispatchPayload):
{
  "lines": [
    {
      "line_key": "1",                      // see line_key rules below
      "quantity": 10                        // qty to dispatch NOW (can exceed pending)
    },
    {
      "line_key": "job-11-item-19",
      "quantity": 5
    }
  ],
  "extra_items": [
    {
      "item": 25,                           // catalog item id
      "quantity": 3
    }
  ]
}

line_key rules (frontend generates, backend should accept):
  1. If item row has id:     line_key = String(item.id)           e.g. "1"
  2. Else if job+item known: line_key = "job-{jobId}-item-{itemId}" e.g. "job-11-item-19"
  3. Else fallback:          line_key = "idx-{index}"             e.g. "idx-0"

  Utility file: src/features/material-requests/utils/material-request-line-key.util.ts

Business rules:
  - quantity on each line is incremental dispatch amount (added to existing dispatched_quantity)
  - Over-dispatch allowed: total dispatched can exceed requested quantity
  - extra_items are items NOT on the original request (tracked separately)

Expected response:
  Full MaterialRequestDetail after dispatch (same as GET detail), with:
  - updated dispatched_quantity per line
  - new timeline entry
  - extra_dispatch_items appended
  - status auto-updated to partially_dispatched or dispatched
